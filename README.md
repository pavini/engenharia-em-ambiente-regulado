# Engenharia em ambiente regulado

Uma hora alguém vai pedir o histórico completo de uma operação, do primeiro contato
até a decisão. Pode ser a auditoria interna, a externa, o regulador ou o jurídico do
cliente. Este repositório é sobre o que o seu sistema precisa ter para essa pergunta
não virar um problema.

Não é sobre norma. É sobre o que sobra pro time de engenharia quando a norma chega.

## Por que eu escrevi isso

Trabalho com tecnologia há 22 anos, os últimos em serviços financeiros. Fui o ponto
focal de tecnologia em auditoria em três empresas e respondi demandas de regulador
em uma delas. Em todas, a parte difícil nunca foi entender a exigência. Foi descobrir,
sempre tarde, que o sistema tinha sido construído sem ela.

O que existe escrito sobre isso ou é jurídico demais pra ser acionável, ou é material
de fornecedor vendendo ferramenta. Falta a versão de quem escreve o código.

Este repositório é essa versão. Vai crescer conforme eu for escrevendo.

## O que este repositório não é

Não é consultoria jurídica e não substitui o time de compliance da sua empresa.
As exigências mudam por setor, por regulador e por porte. O que está aqui é o
recorte de engenharia: o que precisa existir no sistema para que a resposta seja
possível.

Nada aqui vem de operação, cliente ou empresa específica. Onde cito regulação,
é regulação pública.

vai ser a discussão, não o texto.
